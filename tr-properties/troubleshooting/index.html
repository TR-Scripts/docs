Troubleshooting

Previous Next

A door says it's locked but stays open¶

The game's door system doesn't know the door, which happens with some MLO doors. Run /doorcheck <hash> (with Config.Debug on): if entity is 0 or false, give the door a model. See Setting up a new door.

A locked door stands open at an angle¶

The door's heading is wrong. The heading is the closed one: close the door and read it with /doorscan.

No blips, no buy prompt, doors not locking¶

The server didn't finish loading. Look for a SCRIPT ERROR from tr-properties in the server console, and check that oxmysql started first.

Bought a property but got no key¶

The player's inventory was full. Nothing is charged in that case and they're told to make room. For properties given by command, use /property <id> key.

Using a key says it doesn't fit¶

The locks were changed since that key was cut, or it's a key to another property. The key's description shows its lock serial.

Storage doesn't show¶

The property's type must be in Config.Storage, the property must be owned, and the player needs a key that fits (or, with Config.OwnerNeedsKey = false, to be the owner).

A script using tr-properties can't find a property¶

Ids include the type: ranch:hangingdog_ranch, not hangingdog_ranch. tr-properties' own tables use the full id; tr-ranching's and tr-housing's tables keep their own keys.
